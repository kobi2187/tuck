# Review of the bare-metal branch — 2026-11-22

Reviewer stance: a senior embedded developer deciding whether to trust this
for firmware. The question is not "is it impressive" (it is) but "would it
bite me on a board".

Everything below was checked by running it: Nim 2.2.4 (the CI pin), QEMU
8.2.2, arm-none-eabi-gcc 13.2.1, vendored picolibc 1.8.12, gdb-multiarch 15.1,
Odin `b2354a04`, dmd 2.112. A finding marked **FIXED** has a regression test.

## Verdict

The direction is right, and better than most hobby embedded-language efforts.
Diagnostics are honest, formats are standard (SARIF, DWARF), the fault decoder
is genuinely useful, and the plan's discipline (record what each wrong answer
taught) is rare. The first ten metal stages are real: tasks interleave on
QEMU, a precise fault decodes to the Tuck line, the SVD path works across
module boundaries.

But the branch was **green on tests that could not fail in the ways that
matter**. Three classes of bug were invisible to the suite:

1. *Concurrency primitives that were wrong exactly when used for real*
   (nesting, early return, an ISR firing between two task instructions).
2. *Every failure on metal looked like success* (a hang ended in the idle loop,
   exit 124 meant "clean").
3. *No real interrupt was ever taken*. Every `[irq]` fn in every stage is
   called from `main` like a normal function. The ISR rules are checked
   statically but have never met preemption.

The first two are fixed on this branch. The third is the most important open
item: it is what "first-class bare metal" depends on.

## Open — ranked by how badly it would bite on a real board

1. **No interrupt is ever really taken.** The vector table has 16 entries (no
   external IRQs). There is no way to bind an `[irq]` fn to a vector, so every
   ISR test is a function call from `main`. Needed: a vector declaration
   (`[irq: USART1]` or an `interrupt` decl the board maps to a slot), a
   generated table, and a QEMU stage where a real SysTick or UART interrupt
   preempts a task. *Until this exists the ISR discipline is a static check
   with no runtime proof.*
2. **No timed wait.** On metal, `tuckSlOnStack` runs a pausing extern inline,
   so `delayMs` is a busy-wait that blocks every task. There is no SysTick
   interrupt, no timer wheel, no `WFI` when the ready list is empty (the idle
   path spins at 100% CPU). "Blink at 1 Hz while handling UART", the first
   real firmware, cannot be written yet. Needs item 1.
3. **Register writes are read-modify-write of the whole word.** Writing one
   field of a register with write-1-to-clear status bits (USART SR, timer SR,
   EXTI PR) clears every pending flag that happened to read 1. svd2tuck drops
   SVD's `modifiedWriteValues` "with a note", which is exactly the information
   needed. A field write also isn't atomic against an ISR touching another
   field of the same register. Needs a `[w1c]`/write-only-field spelling and
   a codegen rule (write the mask only; never RMW a w1c register).
4. **Unoptimised builds.** The freestanding build passes no `-O`/`-Os`,
   no `-ffunction-sections -fdata-sections -Wl,--gc-sections`. Every register
   write is three calls plus error-flag checks; `tuckEventDump` is 614 bytes.
   Timing scores (`cost_model`) and any real latency are meaningless until the
   build is optimised. Turning it on will also flush out volatile/ordering
   bugs that -O0 hides; do it next, behind the QEMU suite.
5. **RAM baseline is ~4.6 KB before user code**: 2 KB frame heap, 1.25 KB
   event ring, 1 KB `tuck_tls`. That is 57% of the 8 KB stm32vldiscovery part.
   The TLS block exists only because Nim still emits `__thread` access for
   the error flag under `--threads:off`; generating plain globals for
   freestanding (or `-ftls-model=local-exec` plus a real `.tdata/.tbss`)
   removes the GOT dance, the asm `__aeabi_read_tp` and the stm32 `.got` copy.
6. **Linker scripts are QEMU-grade.** No `.stack` reservation or check that
   `.bss` + stack fits; initial SP is a `-D` define, not
   `ORIGIN(RAM)+LENGTH(RAM)`; no `ALIGN(4)` before `_edata`/`_ebss` (the word
   copy loop can overrun 3 bytes); `.got` handled on one board only; no
   `.noinit` for the fault record, so it is zeroed by the reset a watchdog
   would trigger, the one moment it is needed. `flip-link` (planned, H7) is
   not done.
7. **Semihosting is the only output channel.** On silicon without a debugger,
   `BKPT 0xAB` escalates to HardFault; inside the fault handler that is a
   lockup. Every `say`, `PANIC` and the fault line need a UART/ITM/RTT
   backend before the first real board. (`tuck_board_exit` and `tuck_fatal`
   are now the two seams for it.)
8. **The fault handler assumes MSP.** `mov r0, sp` is right only while
   nothing runs on PSP; the standard `tst lr,#4; ite eq; mrseq/mrsne` costs
   four instructions and survives a future RTOS-style split.
9. **SysTick clock comments are wrong for silicon.** `clock_init` never sets
   `CSR.CLKSOURCE`, so on an STM32F1 it counts HCLK/8, not CPU cycles. The
   1000-read warm-up is a QEMU workaround baked into a "reusable" module, and
   24-bit wrap (233 ms at 72 MHz) without a SysTick ISR gives no long time
   base. Needs item 1.
10. **Stage tests use peripheral space as scratch.** `register FLAG at
    0x40000000` is the LM3S watchdog load register and STM32 TIM2_CR1. The
    LED stages use STM32 addresses on the LM3S board, and QEMU emulates
    neither GPIO block, so "LED blinks" has never been observed. Use SRAM for
    scratch (as the new stages do) and read back GPIO where QEMU models it.
11. **"Fault injection" is a compile-time bool the program reads itself**
    (`faultIsrDrop`); it cannot find a bug the author did not write a branch
    for. Real injection perturbs from outside: drop or duplicate a real
    interrupt (needs item 1), flip a register via the gdbstub, exhaust a pool.
12. **Metal is Nim-only.** Odin and D have hosted no-op `critical:` and no
    freestanding runtime. Fine for now, but say so in a support matrix (vision
    §8.3 #19) before anyone reads "three backends" as "three metal backends".
13. **`--debug-lines` attributes the entry wrapper to the `.tuck` file**
    (gdb shows `task_await.tuck:36/47/52` in a 15-line file for
    `NimMainInner`/`NimMain`/`main`). Harmless today; confusing in a
    backtrace.
14. **An ISR's own unprotected access is flagged** even though a task cannot
    preempt it. (This item also claimed the audit's name-keyed state could
    confuse a local with a register of the same name; checked 2026-11-22, it
    cannot: the checker refuses `var FLAG = n` beside `register FLAG` with
    "cannot assign int to FLAG". Withdrawn.) That pushes users toward unnecessary critical sections inside
    handlers, which costs latency. Protection belongs on the preemptible side.
