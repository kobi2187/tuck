The design idea, which the next cross-module bug will probably want too: a
library cannot name what an importer defines, so **the importer hands over a
function reference** (or, for data, it moves to a module both import). It is
ordinary emitted code; link-time symbols were tried first and dropped as too
implicit. The proposal doc has the detail and the rejected options.

## 3. Known limits of what was just built

Each of these is a deliberate cut, not a surprise.

- **A27 refusals.** A moved object that composes another declaration (`+ ...`)
  and a moved type with member fns are refused with a message naming the type.
  A satisfier whose data uses a const-sized array of an importer's const is not
  specially handled (the const is not moved). Single-module interfaces are
  unchanged.
- **A27 and `TUCK_TRACK`.** A Seq field of a satisfier whose data moved is not
  handed back at exit under the Odin tracker (the exit release only walks the
  entry module's own actors/types). Same for an imported actor's Seq fields.
- **A34 scope.** Only a plain bound by a group without type parameters of its
  own, on a type parameter some parameter names outright. Everything else
  resolves by name as before. **A14** (two implementations of one requirement
  both visible to the bounded fn) is *not* addressed: the provider is chosen by
  the fn's own module, then by `self` type at the call site.
- **Heartbeat.** No queue-depth reading and no `waitUntil` timeout (issue #74
  asks for both; MISSING-FEATURES §C). In `--actors:single` a blocked handler
  blocks the caller too, so the reply's *timestamp* decides, not the wait.
- **Generated module names are fixed.** `iface_variants` is one module per
  program; a user module of that name would collide.

## 5. Traps found on the way (each cost time)

- **Whole-program tables must survive `resetResolution`.** Typechecking resets
  `semLayer`; a table filled before it (like `handlerSites`) is wiped unless it
  is carried across in `resolution.nim`. The symptom is a feature that silently
  does nothing.
- **`realModules` excludes the entry module** (`prog[^1]`). Any cross-module
  lookup from a *library* module cannot see the entry's declarations; that is
  why `handlerSites` is a program-wide table of ids rather than a scan.
- **`prog[^1]` is the entry module.** Anything that inserts a module must keep
  it last (`iface_hoist.dependencyFirst`).
- **Modules served from the signature index have no declarations.** Anything
  that is not a plain fn forces a full load (`modules.servedBySigs`); a feature
  that reads another module's declarations depends on that.
- **Nim imports are unqualified.** Two modules both defining `tuckRegister`
  make the call ambiguous; the entry calls `module.tuckRegister()`.
- **Odin refuses two definitions of one link name** and a bare body-less proc;
  a `foreign import x "system:c"` block is the only same-program route. Odin and
  D resolve names where a generic is written.
- **A registry handler's `d.name` is mangled** (`tuckˑfnˑAppEvents.Low`); the
  *written* name is `writtenName(d)`. Match on that.
- **`import time` is not transitive**: a type is visible only from a module's
  direct imports. A moved type is re-imported by every module that is not a
  dependency of the generated module.
- **The complexity ratchet fires on any proc you grow past 14.** Extract a
  helper; never raise the limit.
- **Shell:** `git stash` on a clean tree followed by `git stash pop` applies an
  *old* stash and leaves conflicts. `git checkout <file>` throws away
  uncommitted edits to it. Both happened; neither loses committed work.
