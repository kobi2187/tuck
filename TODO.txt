## WHERE THIS IS GOING

Tuck: named-struct dataflow language for embedded and systems work.
Transpiles to Nim and Odin — both real, both run-verified, no interpreter.
The bet: postfix payload calls + effects + actors give rapid-dev ergonomics
without giving up metal access or predictable codegen.

Standing rule (stdlib-blocks.md line 9): allow ALL hardware and OS access.
If users are not limited there, and have actors/concurrency/rapid-dev
skeletons to build on, they fill in what is missing themselves.

No surprises is the other standing rule, and it outranks brevity. On
embedded, a silently-wrong numeric or an implicit conversion is worse than a
character of typing (see R1).

Where it stands 2026-07-28:
  DONE   lexer, parser, effect checker, bidirectional typechecker, lowering
  DONE   two backends at parity — Nim and Odin, 31 compile / 8 run-gated
  DONE   actors + coroutine runtime (minicoro) on both
  DONE   C FFI complete: fns, cstring, structs by value, enums with explicit
         values, callbacks, opaque handles — run-verified against real C
  NOW    the stdlib bottom layer (stdlib-blocks.md) — mostly extern-direct,
         gated on two rulings (D1 generic containers, D2 bytes repr)
  NEXT   async that actually suspends (G1/G2), then the embedded set

Milestone shape, not a schedule:
  M1 language core + one backend            DONE
  M2 second backend at parity               DONE
  M3 C FFI good enough for a real library   DONE (zlib; ImGui-class next)
  M4 stdlib bottom layer usable             IN PROGRESS

  M6 self-hosting or a shipped program      NOT STARTED — the actual proof

## RULINGS (decided; implement when the line comes up)

R1   2026-07-28   `/` is REMOVED. Integer divide is `/i`, float divide is `/f`.
                  No inference, no promotion, no surprise on embedded — the
                  operator names the arithmetic. Kills B3 at the root rather
                  than patching which `/` codegen picks. Applies to `/=` too:
                  `/i=` and `/f=`. Mixed operands are a type error, not a
                  silent widen.
R2   2026-07-28   `if` is an EXPRESSION. `let x = if c: a else: b` is legal.
                  An if used as a value must have an else; one used as a
                  statement still need not.
R3   2026-07-28   `match` is an EXPRESSION too, same rule — arms yield values,
                  exhaustiveness already checked, so a value-position match
                  needs no fallback arm when the domain is covered.
