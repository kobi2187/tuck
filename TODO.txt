## WHERE THIS IS GOING

Tuck: named-struct dataflow language for embedded and systems work.
Transpiles to Nim and Odin — both real, both run-verified, no interpreter.
The bet: postfix payload calls + effects + actors give rapid-dev ergonomics
without giving up metal access or predictable codegen.

Standing rule (stdlib-blocks.md line 9): allow ALL hardware and OS access.
If users are not limited there, and have actors/concurrency/rapid-dev
skeletons to build on, they fill in what is missing themselves.

No surprises is the other standing rule, and it outranks brevity. On
embedded, a silently-wrong numeric or an implicit conversion is worse than a
character of typing (see R1, R5).

Numerics in one line: the source always says what happens. `/i` vs `/f` names
the arithmetic (R1); `~T` marks a conversion that can lose something and `^T`
one that cannot (R5); a declared type never moves on its own (R6). Correctness
and byte-size control pull in opposite directions — auto-promoting to the
widest type would give correctness and wreck embedded layout — so the answer
is neither: nothing is implicit, and the marks cost one character.

## RULINGS (decided; implement when the line comes up)

R1   2026-07-28   `/` is REMOVED. Integer divide is `/i`, float divide is `/f`.
                  No inference, no promotion, no surprise on embedded — the
                  operator names the arithmetic. Kills B3 at the root rather
                  than patching which `/` codegen picks. Applies to `/=` too:
                  `/i=` and `/f=`. Mixed operands are a type error, not a
                  silent widen.
R2   2026-07-28   `if` is an EXPRESSION. `let x = if c: a else: b` is legal.
                  An if used as a value must have an else; one used as a
                  statement still need not.
R3   2026-07-28   `match` is an EXPRESSION too, same rule — arms yield values,
                  exhaustiveness already checked, so a value-position match
                  needs no fallback arm when the domain is covered.
R4   2026-07-28   match arms take EITHER `Pat: body` or `| Pat -> body`. The
                  arrow form is what decision tables and select arms already
                  use, so one shape reads across every pattern construct.
R5   2026-07-28   Numeric conversion is EXPLICIT AND SIGILLED. Two marks:
                    ~T   lossy   — may lose precision, range or meaning
                    ^T   widening — cannot lose anything; optional, never wrong
                  A lossy conversion WITHOUT `~` is a hard error, not a
                  warning. A warning would compile, ship, and lose the bits
                  anyway; the error message names the `~T` that fixes it.
                  `compatible()`'s loose numeric widening goes away — today it
                  lets i64 -> u8 through the checker and the failure surfaces
                  as a Nim error about generated code the user never wrote.
                  What counts as LOSSY (needs ~):
                    - narrowing:      u32 -> u8, i64 -> i32
                    - signed<->unsigned at ANY width: i32 -> u32, because
                      -1 becomes 4294967295 — no bits lost, meaning lost
                    - float -> int (truncates), and int -> float above the
                      mantissa (2^53 for f64, 2^24 for f32)
                  `~` names that loss happens; the TARGET TYPE'S ATTRIBUTE
                  says what happens: [saturating] clamps, [wrapping] wraps,
                  [trapping] traps. A plain type with no attribute TRAPS —
                  loudest default. This makes those attrs load-bearing rather
                  than decorative, so B1 (Odin ignores [saturating]) becomes a
                  blocker for this ruling, not a cosmetic gap.
R6   2026-07-28   Declared types NEVER move. A u8 field is a byte, always: no
                  promotion, no inference rewriting a declaration. Arithmetic
                  does not auto-widen — u8 + u8 stays u8 and overflows per the
                  type's attribute (auto-widening to int is the C mistake and
                  costs bytes). Literals are range-checked at compile time:
                  `let x: u8 = 300` is an error, not a wrap. Embedded keeps
                  exact byte control, and struct layout stays predictable —
                  which matters now that Tuck structs cross the C FFI boundary,
                  where layout IS the ABI.
